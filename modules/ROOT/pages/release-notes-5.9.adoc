= Tapestry 5.9

Tapestry 5.9 moves the framework to Jakarta EE 9.
Every module that touches the Servlet, Persistence, Validation or CDI APIs now compiles against the `jakarta.*` packages instead of `javax.*`.

Because that is a breaking change for existing applications, 5.9 is released twice from two branches:
the Jakarta build publishes artifacts with a `-jakarta` suffix, and the javax build keeps the historical, unsuffixed artifact names.
Both carry the same version number and the same features.
See xref:jakarta-ee-migration.adoc[] for what this means for your project and how to move over.

== Tapestry 5.9.0
Tapestry 5.9.0 is a major release built on Jakarta EE 9.

Highlights:

* issue:2741[] and issue:2788[] - *Jakarta EE 9 support.*
Tapestry now targets Jakarta Servlet 5.0, Jakarta Persistence 3.0, Jakarta Validation 3.0 and Jakarta Inject 2.0.
The corresponding `javax.*` imports in your own code have to be changed to `jakarta.*`.
* issue:2785[] - *Separate artifacts for the Jakarta and javax builds.*
The Jakarta build publishes `tapestry-core-jakarta`, `tapestry-ioc-jakarta` and so on, while the javax build keeps publishing `tapestry-core`, `tapestry-ioc` and so on.
This lets both live side by side in Maven Central at the same version, so projects that cannot move to Jakarta yet can still pick up 5.9.
* issue:2793[] - *New javadoc:org.apache.tapestry5.corelib.components.Recursive[] component.*
A javadoc:org.apache.tapestry5.corelib.components.Loop[]-like component that renders its body recursively over parent/child data such as trees and menus, with javadoc:org.apache.tapestry5.corelib.components.RecursiveBody[] marking the insertion point for the children.
Objects are adapted to the component through javadoc:org.apache.tapestry5.commons.RecursiveValueProvider[] implementations.
This was contributed by https://www.pubfactory.com[KGL PubFactory].
* issue:2799[] - *Session locking is now explicit.*
Reading from a javadoc:org.apache.tapestry5.http.services.Session[] could lock up a thread.
The fix introduces `Session.LockMode` (`NONE`, `READ`, `WRITE`) together with `getAttributeNames(LockMode)` and `getAttributeNames(String, LockMode)` overloads, so the lock a call acquires is now something you can control.
See xref:session-storage.adoc#_session_locking[Session Locking].
* issue:2782[] - The client-side `t5/core/ajax` function accepts an `options.headers` object, so application code can add custom headers to Ajax requests.
* issue:2789[] - A migration tool was added to help rewrite Maven and Gradle builds onto the suffixed artifact names.
* A large round of dependency upgrades came with the Jakarta move, including Hibernate Validator 8, EclipseLink 3.0, Spring 6, Jetty 11 and Apache Commons FileUpload 2.

[IMPORTANT]
====
`tapestry-spring` now depends on Spring 6, which requires *Java 17*.
The rest of Tapestry still builds for Java 8 bytecode and is tested on Java 11 and 17.
====
